Summary

The changes adapt once to a local big-config checkout, make provider selection come from workflow parameters instead of hardcoded render values, and remove the dependency on big-tofu.core helpers for SMTP DNS JSON generation.

Intent

The main direction is to make the rendering layer more data-driven and resilient to upstream big-config API changes:

  • Provider values are now read from ::workflow/params. This lets BC_PAR_PROVIDER_* overrides drive template selection.
  • The backend render plugin is registered through a compatibility shim. It supports both the older multimethod API and a newer registration function when available.
  • Terraform JSON construction is local to once. SMTP DNS records are generated without importing big-tofu.core.
  • Tofu output reads are quieter. Failed tofu output --json attempts capture stderr before falling back to development defaults.

deps.edn

big-config is now loaded from local source instead of the pinned git SHA.

- io.github.amiorin/big-config {:git/sha "12f853026d7758b18942c73b541e0b6b1f77f773"}
+ io.github.amiorin/big-config {:local/root "../../big-config/clojure"}

This is useful when developing once against in-progress big-config changes. It does mean the project now expects that relative checkout to exist when running commands locally.

Release noteIf this change is only for local development, re-enable the git dependency before publishing or handing the repo to someone without the sibling big-config/clojure checkout.

params.clj

Both tofu-params and tofu-smtp-params now call tofu output --json with :err :string as well as :out :string.

(p/shell {:dir dir
          :out :string
          :err :string} "tofu output --json")

The functional behavior is the same: successful output is parsed into workflow params; failures still fall back to placeholder values such as {:ip "192.168.0.1"} or {:id "domain-id-not-defined" :records []}. The practical change is that stderr is captured instead of leaking Tofu diagnostics into the terminal during expected fallback paths.

tools.clj

Provider values come from parameters

A new helper centralizes provider lookup:

(defn- provider-param
  [opts k default]
  (or (get-in opts [::workflow/params k]) default))

The render setup for each Tofu stage now uses this helper instead of fixed strings:

StageParameterDefault
tofu:provider-compute"hcloud"
tofu-smtp:provider-smtp"resend"
tofu-dns:provider-dns"cloudflare"
tofu-smtp-post:provider-smtp"resend"
render-tofu-backend:provider-backend"s3"

Because workflow/read-bc-pars already maps BC_PAR_* environment variables into ::workflow/params, provider switching can now be driven from the environment:

export BC_PAR_PROVIDER_COMPUTE=digitalocean
export BC_PAR_PROVIDER_BACKEND=local

Backend plugin registration is API-compatible

The old inline defmethod was replaced by a named handler and a registration helper:

(defn- register-plugin-handler!
  [step handler]
  (if (instance? clojure.lang.MultiFn pluggable/handle-step)
    (.addMethod ^clojure.lang.MultiFn pluggable/handle-step step handler)
    (if-let [register (ns-resolve 'big-config.pluggable 'register-handle-step)]
      (@register step handler)
      (throw (ex-info "Unsupported big-config.pluggable API" {:step step})))))

This keeps once working if big-config.pluggable/handle-step is still a multimethod, while also supporting a newer API that exposes register-handle-step.

SMTP DNS JSON is generated without big-tofu.core

The import of big-tofu.core was removed. In its place, tools.clj defines small local helpers:

  • add-fqn-suffix appends a suffix to a keyword while preserving its namespace.
  • tofu-fqn->name converts namespaced keywords into Terraform-safe names by replacing hyphens and dots with underscores.
  • tofu-construct builds the nested Terraform JSON resource map directly.
(defn- tofu-construct
  [group type fqn block]
  {group {type {(tofu-fqn->name fqn) block}}})

The resulting render-fn still emits Cloudflare DNS records for Resend SMTP verification, but it no longer depends on ->Construct, add-suffix, or construct from big-tofu.core.

Behavior changes

Provider overrides are effective during render

:provider-compute, :provider-backend, :provider-smtp, and :provider-dns can be supplied through params.
  • Defaults preserve the previous behavior.
  • Environment overrides now affect the transform selector.

Tofu output fallback is quieter

stderr is captured when output directories or state are not ready.
  • Fallback params are unchanged.
  • Expected dev-time failures are less noisy.

Plugin registration supports two APIs

The backend render step can register against either a multimethod or a registry function.
  • Improves compatibility with local big-config work.
  • Throws a clear error if neither API exists.

Terraform JSON naming is explicit

Generated resource names are sanitized locally.
  • Hyphens and dots become underscores.
  • Namespaced keywords include namespace + name.

Compatibility notes

  • The local big-config dependency requires ../../big-config/clojure to exist relative to this repo.
  • The old hardcoded defaults are preserved when provider params are missing.
  • The new plugin registration code deliberately fails fast with Unsupported big-config.pluggable API if the loaded big-config exposes neither supported registration mechanism.
  • Removing big-tofu.core imports narrows coupling to big-tofu, but any downstream expectation about exact generated Terraform resource names should be checked.
