# Plan 05 — `bb describe`

## Goal

Add a human-readable `bb describe` command for the **active profile** (`options/bb`).
It should show:

1. The configured provider names: compute, backend, SMTP, DNS.
2. Whether compute is reachable/running, using the IP + SSH user resolved by
   `(params/once-opts options/bb)` and an SSH probe.
3. The applications deployed on the remote server, including host, image tag,
   running image digest, registry digest for the same tag, and whether the tag
   has a newer digest available.

If nothing has been provisioned or SSH is unreachable, the command should not
error; it should print that compute is not reachable/running and skip the remote
application details.

## Scope / decisions

- **Output**: human-readable only.
- **Profile**: active profile only (`options/bb`), with `BC_PAR_*` overrides
  applied through `params/once-opts`.
- **Compute status**: no cloud-provider API calls. Resolve `:ip` and `:user`
  from `(params/once-opts options/bb)`, then run a short, non-interactive SSH
  command.
- **No-infra**: same path as cloud compute; `params/once-opts` resolves the
  configured IP/user and SSH decides reachability.
- **Failure mode**: soft-fail. Missing Tofu state, unreachable SSH, missing
  remote tools, missing local `skopeo`, or unparseable output should appear as
  `unknown` / `not reachable` details in the report, not as a non-zero command
  failure.
- **Applications source**: remote server, not local `:once :applications`.
- **Version**: Docker tag (`latest` if no tag is present).
- **New version check**: compare the digest of the running/local image on the
  remote host with the digest currently published by the registry for the same
  image tag.

## Deliverables

### 1. New namespace: `io.github.bigconig-ai.once.describe`

File: `src/clj/io/github/bigconig_ai/once/describe.clj`

Public API:

- `describe opts` — returns a data map suitable for printing:

  ```clojure
  {:profile "website"
   :providers {:compute "digitalocean"
               :backend "r2"
               :smtp "resend"
               :dns "cloudflare"}
   :compute {:ip "203.0.113.10"
             :user "root"
             :running? true
             :detail "ssh ok"}
   :applications [{:host "www.example.com"
                   :status "running"
                   :image "ghcr.io/org/app:latest"
                   :version "latest"
                   :digest "sha256:..."
                   :registry-digest "sha256:..."
                   :new-version? false}]}
  ```

- `describe* args & [opts]` — CLI entry point, defaults to `options/bb`, prints
  a human-readable report, and returns the same data map. It should not call
  `System/exit 1` for unreachable infrastructure.

Structure should mirror `validation.clj`: docstring, private command helpers,
pure parsers, top-level `describe`, printer, `describe*`, and a `comment` block
for REPL examples.

### 2. Provider summary

From the params produced by `params/once-opts`, collect:

```clojure
{:compute (:provider-compute params)
 :backend (:provider-backend params)
 :smtp    (:provider-smtp params)
 :dns     (:provider-dns params)}
```

Do not print credential/token values.

### 3. Compute reachability

Resolve:

- `:ip` from `::workflow/params` after `params/once-opts`.
- `:user` from `::workflow/params`; fallback to `:sudoer`, then `"root"`.

SSH probe command:

```bash
ssh -o BatchMode=yes \
    -o ConnectTimeout=5 \
    -o StrictHostKeyChecking=accept-new \
    <user>@<ip> true
```

Implementation notes:

- Use `babashka.process/process` with an argv vector and a timeout, similar to
  `validation.clj`.
- Treat exit `0` as `:running? true`.
- Treat any non-zero exit, timeout, blank/missing IP, or thrown exception as
  `:running? false` with a short `:detail` string.
- `params/tofu-params` currently falls back to `192.168.0.1` when Tofu output is
  missing. For cloud compute profiles, avoid presenting this as a guaranteed
  real IP; if SSH fails, print a clear “not reachable / no Tofu output or host
  down” style message.

### 4. Remote application discovery

Only run this phase when the SSH probe succeeds.

Use SSH to collect remote state with `sudo -n` so it never prompts for a
password. Prefer separate simple SSH commands over one large fragile command:

1. `sudo -n once list` — source of deployed application hosts/status.
2. `sudo -n docker ps -q` — running container IDs.
3. `sudo -n docker inspect --type container <ids...>` — container image refs,
   state, labels, names.
4. `sudo -n docker image inspect <image-ids-or-image-refs...>` — image
   `RepoDigests`, `Architecture`, `Os`, and image IDs.

If `once`, `docker`, or `sudo -n` fails, keep the compute status as running and
report applications as unavailable with the error detail.

Parsing strategy:

- Reuse the existing host regex idea from the deploy script for `once list`.
  Capture both host and optional status from lines like:

  ```text
  app.example.com (running)
  ```

- Strip ANSI escape sequences before parsing.
- Match Docker containers to hosts by looking for the host in container labels,
  label values such as Traefik/Caddy host rules, or container names. If no
  matching container is found for a host, still report the host with unknown
  image/digest fields.
- The remote server is the source of truth: do not fill missing remote
  applications from local profile config.

### 5. Image tag + digest comparison

Add small pure helpers:

- `image->repository+tag`:
  - `ghcr.io/org/app:1.2.3` → repository `ghcr.io/org/app`, tag `1.2.3`.
  - `ghcr.io/org/app` → repository `ghcr.io/org/app`, tag `latest`, normalized
    image `ghcr.io/org/app:latest`.
- `matching-repo-digest` — from Docker image `RepoDigests`, choose the digest
  whose repository matches the running image repository.
- `registry-digest` — local command:

  ```bash
  skopeo inspect --no-tags --override-os <os> --override-arch <arch> docker://<image:tag>
  ```

  Parse `.Digest` from the JSON output. If `skopeo` is missing or the registry
  check fails, return `nil` plus a detail string.

For each application:

- `:image` = running container image ref from Docker inspect.
- `:version` = Docker tag.
- `:digest` = running/local digest from remote Docker image `RepoDigests`; if
  unavailable, use the Docker image ID as a fallback but mark comparison as
  unknown.
- `:registry-digest` = digest currently published by the registry for the same
  tag.
- `:new-version?`:
  - `true` when both comparable digests exist and differ.
  - `false` when both comparable digests exist and match.
  - `nil` when comparison is unavailable.

### 6. Human-readable report

Example when running:

```text
Profile: website

Providers:
  Compute: digitalocean
  Backend: r2
  SMTP: resend
  DNS: cloudflare

Compute:
  IP: 203.0.113.10
  SSH user: root
  Status: running

Applications:
  - www.example.com
    status: running
    image: ghcr.io/org/app:latest
    version: latest
    digest: sha256:abc...
    registry digest: sha256:abc...
    update available: no
```

Example when not reachable:

```text
Profile: website

Providers:
  Compute: digitalocean
  Backend: r2
  SMTP: resend
  DNS: cloudflare

Compute:
  IP: unknown
  SSH user: root
  Status: not reachable (ssh timed out)

Applications: not checked because compute is not reachable.
```

### 8. Tests

New file: `test/clj/io/github/bigconig_ai/once/describe_test.clj`.

Pure/unit coverage:

- Provider extraction from params.
- Image ref parsing (`:latest` default, explicit tags, registry ports).
- ANSI stripping and `once list` host/status parsing.
- Docker inspect parsing and host-to-container matching from labels/names.
- Digest selection from `RepoDigests`.
- Digest comparison outcomes: update available yes/no/unknown.

Integration-style unit coverage via injected/stubbed command runner:

- SSH failure → `:compute :running? false`, no remote app commands, no throw.
- SSH success + remote command failure → compute running, applications reported
  unavailable, no throw.
- SSH success + remote app/image data + stubbed registry digest → app report has
  host, image, version, digest, registry digest, and `:new-version?`.

Do not run real SSH, Docker, or registry calls in tests.

Run with:

```bash
clojure -M:test
```

## Out of scope

- Describing profiles other than `options/bb`.
- JSON / machine-readable CLI output.
- Cloud-provider API status checks.
- Changing the deployment flow or Ansible ONCE module.
- Using local profile applications as a fallback source of truth.

## Open questions resolved

- Human-readable output only.
- Include compute, backend, SMTP, and DNS providers.
- Active profile only.
- Use `params/once-opts` and SSH for compute status, including no-infra.
- No hard error when nothing is running.
- Applications come from the remote server.
- Version means Docker tag; digest means image digest.
- New version means running/local digest differs from current registry digest for
  the same tag.
