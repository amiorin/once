# Plan 02 — Validation for options + tools

## Goal

Add a `bb validate` command that, for the **active profile** (`options/bb`), checks:

1. The merged options map conforms to a malli schema (structure + formats + cross-field rules).
2. All required CLI tools are installed.
3. All credentials/tokens work against their respective APIs.
4. All Docker images referenced by `:once {:applications [...]}` exist on their registry.

Failures are collected and reported in a single pass. Validation is opt-in via `bb validate`; it does not auto-run before `bb once create`.

## Scope

- **Active profile only** — whatever `options/bb` resolves to.
- `BC_PAR_*` env overrides are folded in before validation (via `workflow/read-bc-pars`); `tofu-params` / `tofu-smtp-params` are skipped (they read state from a not-yet-deployed stack).

## Deliverables

### 1. New namespace: `io.github.bigconig-ai.once.validation`

File: `src/clj/io/github/bigconig_ai/once/validation.clj`

Public API:
- `validate opts` — returns `{:ok? boolean, :errors [{:check kw, :detail string} ...]}`.
- `validate* args & [opts]` — CLI entry point. Pretty-prints the report; `System/exit 1` on failure.

Pipeline inside `validate`:
1. Apply `workflow/read-bc-pars` to fold `BC_PAR_*` into `::workflow/params`.
2. Run schema validation → collect errors.
3. Run tool-existence checks → collect errors.
4. Run credential smoke tests → collect errors.
5. Run image smoke tests → collect errors.

All four phases run regardless of earlier failures (collect-all, no fail-fast).

### 3. Malli schemas (strict)

**Sub-profile schemas** — one per composable building block in `options.clj`:

| Schema | Required keys |
|---|---|
| `Deploy` | `:deploy-pubkey` (matches `^ssh-(ed25519|rsa|...) `) |
| `Resend` | `:provider-smtp = "resend"`, `:resend-server`, `:resend-port int`, `:resend-username`, `:resend-api-token` (from `BC_PAR_*`) |
| `Cloudflare` | `:provider-dns = "cloudflare"`, `:cloudflare-api-token` (from `BC_PAR_*`) |
| `S3` | `:provider-backend = "s3"`, `:s3-bucket`, `:s3-region` |
| `Local` | `:provider-backend = "local"` |
| `Oci` | `:provider-compute = "oci"` + the 10 `:oci-*` keys |
| `Hcloud` | `:provider-compute = "hcloud"` + the 5 `:hcloud-*` keys + `:hcloud-token` |
| `DigitalOcean` | `:provider-compute = "digitalocean"` + the 6 `:digitalocean-*` keys + `:digitalocean-token` |
| `NoInfraCompute` | `:provider-compute = "no-infra"` + the 5 `:no-infra-compute-*` keys |
| `NoInfraSmtp` | `:provider-smtp = "no-infra"` + matching keys |
| `NoInfraDns` | `:provider-dns = "no-infra"` |

**Top-level `Profile` schema**:
- Requires `::render/profile` (string), `::workflow/params` (map).
- Inside `::workflow/params`: requires `:domain` (regex: domain), `:package` (non-empty string), `:once` (map with `:applications` vector).
- Each `:applications` entry: `:host` (regex: hostname), `:image` (regex: registry ref like `ghcr.io/<org>/<name>(:<tag>)?`), optional `:env` (vector of strings).
- Branches on the four `:provider-*` discriminators using `:multi` schemas, merging in the matching sub-profile schema.

**Cross-field rule**: every `(get-in % [::workflow/params :once :applications i :host])` must equal or be a subdomain of `(get-in % [::workflow/params :domain])`. Implemented as a `[:fn ...]` predicate on `Profile` that returns explanation strings via `malli.core/explain`.

**Format regexes**:
- Domain: `^[a-z0-9]([a-z0-9-]*[a-z0-9])?(\.[a-z0-9]([a-z0-9-]*[a-z0-9])?)+$`
- Hostname (for `:host`): same as domain
- Image ref: `^[a-z0-9.-]+/[a-z0-9._-]+(/[a-z0-9._-]+)*(:[a-zA-Z0-9._-]+)?$`
- SSH pubkey: `^ssh-(ed25519|rsa|dss|ecdsa) [A-Za-z0-9+/=]+( .*)?$`

### 4. Tool existence checks

Defined as data:

```clojure
(def base-tools
  [{:cmd "tofu"            :name "OpenTofu"  :hint "https://opentofu.org/docs/intro/install/"}
   {:cmd "ansible-playbook":name "Ansible"   :hint "pipx install ansible"}
   {:cmd "ssh"             :name "OpenSSH"   :hint "your distro's openssh-client package"}
   {:cmd "curl"            :name "curl"      :hint "your distro's curl package"}
   {:cmd "skopeo"          :name "skopeo"    :hint "https://github.com/containers/skopeo/blob/main/install.md"}])

(defn provider-tools [provider-compute provider-backend]
  (cond-> []
    (= provider-compute "oci")          (conj {:cmd "oci"   :name "OCI CLI"  :hint "..."})
    (= provider-compute "hcloud")       (conj {:cmd "hcloud":name "hcloud"   :hint "..."})
    (= provider-compute "digitalocean") (conj {:cmd "doctl" :name "doctl"    :hint "..."})
    (= provider-backend "s3")           (conj {:cmd "aws"   :name "AWS CLI"  :hint "..."})))
```

Detection: `(p/sh {:out :string :err :string} "command" "-v" cmd)` — exit 0 means present. On miss, error string is `"<name> not found on PATH. Install: <hint>"`.

### 5. Credential / API smoke tests

One test fn per credential. Each runs a shell command via `babashka.process/sh`, treats exit 0 as pass, otherwise grabs stderr+stdout snippet for the error report.

| Active when | Command |
|---|---|
| `:provider-smtp = resend` | `curl -sf -o /dev/null -H "Authorization: Bearer $TOKEN" https://api.resend.com/api-keys` |
| `:provider-dns = cloudflare` | `curl -sf -o /dev/null -H "Authorization: Bearer $TOKEN" https://api.cloudflare.com/client/v4/user/tokens/verify` |
| `:provider-compute = hcloud` | `curl -sf -o /dev/null -H "Authorization: Bearer $TOKEN" https://api.hetzner.cloud/v1/server_types` |
| `:provider-compute = digitalocean` | `curl -sf -o /dev/null -H "Authorization: Bearer $TOKEN" https://api.digitalocean.com/v2/account` |
| `:provider-compute = oci` | `oci iam region list --output json` |
| `:provider-backend = s3` | `aws sts get-caller-identity` |

Tokens are pulled from the merged `::workflow/params` (already populated by `read-bc-pars`). If the schema phase already flagged a missing token, the smoke test is skipped for that credential to avoid duplicate noise.

### 6. Docker image smoke tests

For each `:image` in `(get-in opts [::workflow/params :once :applications])`:

```
skopeo inspect --no-tags docker://<image>
```

Exit 0 = exists. Non-zero = error including the image ref and stderr snippet.

### 7. CLI / bb wiring

In `bb.edn`:

```clojure
:requires (... [io.github.bigconig-ai.once.validation :as validation])
validate {:doc  "validate active profile, tools, credentials, and docker images"
          :task (validation/validate* *command-line-args* options/bb)}
```

`validate*` prints either `All checks passed.` or:

```
Validation failed (N issues):

  Schema:
    - :resend-api-token is required (BC_PAR_RESEND_API_TOKEN)
    - :applications[0].host "wrong.com" is not a subdomain of :domain "bigconfig.website"

  Tools:
    - skopeo not found on PATH. Install: https://github.com/containers/skopeo/...

  Credentials:
    - Cloudflare token rejected (HTTP 401)

  Images:
    - ghcr.io/bigconfig-ai/once-bigconfig:latest — manifest unknown
```

Exit 1 if any issues.

### 8. Tests

New file: `test/clj/io/github/bigconig_ai/once/validation_test.clj`.

Coverage:
- **Schema**: round-trip every public profile (`options/website`, `options/online`, `options/space`, `options/no-infra`) — they should all conform once stub credentials are merged in. Each profile also gets a deliberately-broken variant (missing required key, bad domain, mismatched applications host) and we assert the right `:check`/`:detail` is reported.
- **Provider-tools selection**: assert `provider-tools` returns the right CLIs for each `provider-compute` × `provider-backend` combo.
- **Cross-field rule**: positive (host = `www.<domain>`) and negative (host on a different domain) cases.
- **Image-ref / domain regexes**: a small parametrised table of valid + invalid examples.

Smoke-test phases (curl/skopeo/etc.) are **not** unit-tested — they are I/O against external services. The schema and tool-selection phases are pure and worth covering.

Run via `clojure -M:test`.

## Out of scope

- Auto-running validation before `bb once create` (deferred — easy to add later by calling `validation/validate` from `package/once` and bailing on `:ok? false`).
- Validating profiles other than the active one.
- Validating value semantics that require state (e.g. confirming the OCI subnet ID resolves) — those belong with the live `tofu plan`.
- Machine-readable (JSON) output. Human-only for now.

## Open questions resolved

- **Code location**: new `validation.clj` namespace.
- **Trigger**: standalone `bb validate` task only.
- **CLI tools used**: `curl`, `skopeo`, plus per-provider CLIs (`oci` / `hcloud` / `doctl` / `aws`).
- **Scope**: active profile (`options/bb`) only.
- **Failure mode**: collect-all, single report.
- **Schema strictness**: strict — required keys + value formats + cross-field consistency.
- **Tests**: malli/tool-selection coverage in `validation_test.clj`; live smoke tests excluded.
