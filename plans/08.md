# Port once/green from big-config to green library

## Context

The once/green project currently depends on the big-config SDK for workflow orchestration, template rendering, and step execution. The user wants to port it to the green library (`/home/ubuntu/code/green`), which provides a DAG workflow engine, an advice system, and built-in tofu/ansible/scaffold primitives.

Key user decisions:
- **CLI**: Self-contained `green` script (`bb green create/delete/build/describe`)
- **SDK steps**: Drop lock/git-check/git-push/unlock-any
- **Params**: Flat keys in opts, loaded from `green.edn`
- **Validation**: Remove entirely
- **Secrets**: `GREEN_PAR_*` env vars override flat keys (so `green.edn` can be committed)

## Approach

### 1. `deps.edn`

Remove: `big-config`, `cheshire`, `babashka/process`, `com.rpl/specter`, `clj-commons/clj-yaml`, `metosin/malli`.
Add: `io.github.amiorin/green {:local/root "/home/ubuntu/code/green"}`.
Green brings `cheshire` and `selmer` transitively.

### 2. `utils.clj` — shared helpers

Add:
- **`shell-cmd [args opts]`** — run command via ProcessBuilder, return `{:exit :out :err}`. Supports `:dir`, `:extra-env`.
- **`run-with-timeout [args opts timeout-ms]`** — like `shell-cmd` but kills process on timeout, returns `{:ok? :exit :out :err}`.
- **`read-green-pars [opts]`** — read `GREEN_PAR_*` env vars, strip prefix, lowercase, replace `_` with `-`, merge into opts. E.g. `GREEN_PAR_DO_TOKEN=xxx` sets `:do-token "xxx"`. This lets users commit `green.edn` with `REPLACE_ME` placeholders and supply secrets via `.envrc.private`.
- **`generate-yaml [data]`** — minimal YAML serializer for the ansible-once playbook format. Replaces `clj-yaml`.

### 3. `tools.clj` — green step functions

Each tool becomes a plain `(opts -> opts)` step function. Renamed: `tofu` → `tofu-compute`, `ansible` → `ansible-remote`.

**Pattern for tofu steps** (tofu-compute, tofu-smtp, tofu-dns, tofu-smtp-post):
```clojure
(defn tofu-compute-step [opts]
  (let [dir (tool-dir opts "tofu-compute")]
    ;; scaffold provider-specific templates
    (sc/scaffold opts [{:template :once.tools.tofu.digitalocean/main.tf
                        :target (str dir "/main.tf")
                        :data opts
                        :opts {:tag-open \< :tag-close \>}}])
    ;; run tofu (create → init+apply, delete → init+destroy, build → skip)
    (if (= :build (:green/event opts))
      opts
      (tofu/tofu-step opts {:dir dir}))))
```

Provider selection: read `:provider-compute` (or `:provider-smtp`, etc.) from opts to pick the right template.

**tofu-dns join handling**: Extract outputs from `:green/branches` (compute IP + SMTP records), merge into opts before scaffolding — same pattern as `green/examples/once`.

**ansible-remote-step**: Scaffold inventory.json + once.yml + static templates, then run `green.ansible/ansible-step`. The `inventory` and `ansible-once` functions stay (inventory uses cheshire; ansible-once uses the new `generate-yaml`).

**ansible-local-step**: Scaffold only (no execution).

**Removals**: `run-steps-with-plugin`, `register-plugin-handler!`, `handle-render-tofu-backend`, all `*` entry points, `step-fns`, `delimiters` def. Backend injection moves to advice in the green script.

**Specter replacement**: `(s/transform [:applications s/ALL] f once)` → `(update once :applications #(mapv f %))`.

### 4. `describe.clj` — flat keys + process helpers

- Direct key access: `(:profile opts)`, `(:provider-compute opts)`, etc.
- `::bc/exit` → `:green/exit`, `::bc/err` → `:green/err`
- `core/ok` → `(assoc opts :green/exit 0)`
- Replace `babashka.process` with `utils/run-with-timeout`
- `describe` signature: `[opts]` instead of `[_step-fns opts]`
- `describe-report` uses `params/once-opts` → simplify to take opts directly (params already resolved by the time describe runs, or for standalone describe, read tofu outputs inline)

### 5. `green.edn` — committable desired state

All config as flat keys. Secrets use `REPLACE_ME` placeholders, overridden by `GREEN_PAR_*` env vars from `.envrc.private`.

### 6. `green` script — entry point + workflow

Pattern follows `green/examples/once/green`:

**Workflow graph** (DAG):
```
create/build:
  start ─┬─► tofu-compute ─┐
         │                  ├─► tofu-dns ──► tofu-smtp-post ──┬─► ansible-local
         └─► tofu-smtp ────┘                                  └─► ansible-remote

delete:
  start ──► tofu-dns ──┬─► tofu-smtp
                       └─► tofu-compute
```

**Wire-fn**: branches on `:green/event` to select create/build vs delete graph.

**Advice**:
- Backend advice (`:before ::backend`) on each tofu step via `tofu/local-backend-advice` (or `s3-backend-advice`)
- `progress/advise` for timing output
- `dry-run/advise` for `--dry-run`

**CLI**:
- `bb green create [--dry-run]` — run workflow with `:green/event :create`
- `bb green delete [--dry-run]` — run workflow with `:green/event :delete`
- `bb green build` — run workflow with `:green/event :build`
- `bb green describe` — call `describe/describe-report` directly (no workflow)
- Loads `green.edn` via `green.cli/run-cli` or manual EDN read, then applies `read-green-pars` to overlay secrets.

### 7. Update tests

**`describe_test.clj`**: `:profile` instead of `::render/profile`, flat params instead of `::workflow/params`, `:green/exit`/`:green/err` instead of `::bc/exit`/`::bc/err`.

**`deploy_test.clj`**: Replace `babashka.process` with `utils/shell-cmd`.

**`utils_test.clj`**: No changes.

### 8. `bb.edn`

Add green dep if Babashka doesn't resolve it transitively from deps.edn.
